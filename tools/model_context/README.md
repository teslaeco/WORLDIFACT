# STANDARD context presentation repair

Draft source and an explicitly gated maintenance installer. Default invocation
is inert. No installation or target runtime attestation is claimed by this
repository; maintenance never submits a paid model or replacement job, resets
a ledger, or changes customer funding.

The existing STANDARD route prints its entire modeling contract into model
history, including repeated original instructions and geometry guidance. Every
subsequent request also receives a long repeated execution/completion guide.
That context is counted again before each model request under the existing cap.

This package changes only the explicit STANDARD initial task and turn guidance.
It supplies the complete losslessly factored scene schema (all 18 primitive
variants and all subject types), original geometry guide, ordered reference
mapping, original prompt and original execution instructions upfront. The first
exec stores the unchanged complete MCP contract and builds the complete scene,
without printing that whole contract. Later access selects the needed fields
from Code Mode store or documented revision/SHA-bound current-model pages.

Required inspection images and current summary can share the existing single
inspection exec. A later model turn must actually assess those pixels before
editing or finishing. Current-revision render and finish gates are unchanged.
This does not claim that any observed job had redundant render calls.

Cabinet, reference-character, FAST and unmarked Froge task/guidance behavior is
unchanged. The original MCP, renderer validator, spend policy, settlement,
completion/continuation rules, images, security and limits are unchanged.
Display `$defs` references never enter the generated scene or canonical validator.

## Reviewed activation boundary (target verification still required)

`oracle_context_launch.py` is the proposed pinned Cloud Shell entry point.
Default invocation downloads nothing and makes no OCI/SSH connection. An
immutable reviewed commit and explicit `--approve-service-maintenance` are
required. Unknown source, package, marker, receipt, service or process evidence
fails closed. Do not run an unfrozen or unreviewed package.

The installer applies only the STANDARD context change, its source-bound health
contract and maintenance gates. It does not activate optional post-hoc exports,
repair old job states or resolve Cloudflare account funding. Other modeling
profiles, provider caps, settlement, credentials, system configuration and model
artifacts remain outside the write set.

Before any live mutation, the exact unprivileged worker, source hashes, existing
receipt chain, original pinned CLI/verifier, private backup paths and target
capabilities must match. A read-only login1 `KillUserProcesses=false` check is
required; the installer does not change that setting. The target must support
pidfds, complete proc/cgroup/socket visibility and process-local subreaping.

The quick-tunnel process stays running so its existing public URL is preserved.
An independent transient guardian freezes only the exact worker pidfd. Every
thread must stop; only the two reviewed baseline threads and the single idle
loopback listener are permitted. Accepted sockets, handler threads, descendants,
containers, unknown source/unit state or **any cancelled/nonterminal/unknown
row** refuse maintenance. Historical cancellations are not cleared or guessed
inactive. The row check repeats under the SQLite admission lock.

With the pinned `Restart=on-failure` unit, verified default/unblocked SIGTERM and
no forced restart/watchdog hooks, the guardian sends TERM+CONT to that pidfd
only. No unit-name stop is used. The worker must exit cleanly and become inactive
without a replacement invocation; the admission lock is then released. A
succeeded/failed worker can still have pending atomic `timing.json` bookkeeping;
that bounded metadata loss is the remaining normal stop tradeoff. Model/provider
work cannot follow those exact terminal exits. Arbitrary concurrent admin,
whole-cgroup or host termination is outside this proof.

Both genuine offline gates run **after** this stop, in a fresh private runtime
stage that contains copied code and validated executables, never live config,
job database, model folders or provider credentials. The inherited generic gate
and the STANDARD CLI/MCP/Blender gate each have a 600-second caller limit. The
STANDARD gate uses inert model/count replies with actual CLI, Code Mode, MCP,
Blender, current images and finish evidence. A process-local subreaper contains
fork/setsid descendants across both gates. Every descendant must exit/reap and
all synthetic containers must be absent before any success attestation. Cleanup
failure keeps live source unmodified and refuses restart until resolved.

Only after these checks does the stopped live worker receive the narrow source
patch and transactional guard/completion/prebuild/generic/context receipts.
The new receipt covers `context_policy.py` and all six inherited core files.
Source/receipt drift prevents overwrite. Original bytes and modes are retained
for rollback; no installed attestation is written before genuine stage proof.

A durable, nonce-bound maintenance marker blocks every non-health route, queue
execution and startup reconciliation while the new worker starts. Authenticated
health must match the exact source receipt and worker invocation in maintenance
mode. Allowed rows are rechecked under admission lock before marker removal.
The installer and lease latch possible activation before attempting unlink.
An unlink that takes effect and then raises is reported as activation-unknown;
no activation retry or rollback follows. That unlink is the activation commit
point. A final health failure afterward is
reported as committed-but-unconfirmed; no blind stop or rollback can interrupt
a newly accepted job. Unknown markers never expire or get removed automatically.

Before activation, rollback re-fences any started worker, restores exact source
and receipt bytes, rechecks rows, and starts the original. Source drift or
uncertain cleanup yields recovery-required instead of a false restoration claim.
The freeze lease is 20 seconds; the installer work alarm is 25 minutes, with
additional bounded cleanup/recovery time and a30-minute transport envelope.
These are control limits, not a guarantee under host failure. Controller death
before deliberate stop is handled by the independent resumer; death after the
worker has intentionally stopped can require operator recovery from backups.

The result distinguishes `activation_committed`, `previous_source_restored`,
fixed refusal codes and verified/unconfirmed phases. No target installation or
live paid model has been run as evidence for this draft. A public command may
only be supplied after exact package freeze and independent integration review.

The read-only login1 property is documented in the official
[systemd login1 interface](https://github.com/systemd/systemd/blob/main/man/org.freedesktop.login1.xml).
No setting is modified to satisfy this precondition.
