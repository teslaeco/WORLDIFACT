## Optional initial construction edit — 8 October 2026

The scene schema cannot express every operation supported by the existing Blender
edit sandbox. In particular, generated image textures, UV mapping and material
alpha require that sandbox. Requiring the JSON scene alone to contain every
requested feature could therefore refuse a supported object before any build.
An observed empty scene response establishes the refusal path, but does not
reveal the provider's unrecorded reason for returning it.

The typed construction response now includes `scene_json` and nullable
`initial_edit`. The scene must contain substantive geometry for every named
component and all defining geometry expressible by the schema. A single bounded
edit may complete the remaining features in the same initial transaction, before
the first inspected candidate. The host validates the edit with the original
sandbox before building; it does not substitute a hardcoded object or accept an
unfinished draft. The original brief and complete modeling contract are retained.

There is still one construction request, followed by actual-render assessment.
The optional later correction and its separate reassessment remain bounded. The
original 8192-token construction allowance, USD 1.75 cap, cancellation, deadline,
request and build limits remain effective. Initial construction reserves the
viable build-plus-edit path before execution. Truncated, invalid, refused and
rejected outputs remain failures; they do not trigger a new paid attempt.

Offline verification exercises a generated-texture globe with UVs and a separate
transparent cloud shell, a different textured object with a later correction,
and the original accepted, rejected and corrected cases. Real native Blender
produced embedded-texture GLBs and current-revision views. The provider plans
and assessments are scripted; the globe's geography is invented. These tests do
not prove photorealistic Earth fidelity, live Astra quality, account-gallery
persistence or Oracle container activation.

The explicit installed upgrade writes exactly three construction helpers and

and receipt set, preserves the seven historical receipts, and runs all four
original isolated gates before activation. The new package refuses the historical
`--update-payload` mode instead of redirecting it to broader writes.
