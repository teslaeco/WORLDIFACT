# Enchanted AI Shop QA — 16 September 2026

Status: **FAIL OBSERVED ON LEGACY PUBLIC FORGE STUDIO / NATIVE WORLDIFACT FIX PREPARED**.

## Owner-device evidence

Android Chrome QA on the public Forge Studio reference showed that pressing the creation/order action did not render a newly generated result on-page. Instead the browser opened a download confirmation for a file named like `FORGE-projekt (3).json`.

This means the legacy public surface behaves as a project brief/export workflow for this action, not as a working end-to-end generation backend. It must not be presented as proof that prompt/image submission currently generates a new 3D asset.

## WORLDIFACT correction

Branch `fix/native-ai-shop-generation-20260916` changes the primary WORLDIFACT `/shop` route so it no longer depends on the legacy Forge Studio iframe for the creation flow.

The native shop surface:

- accepts a text prompt and optional reference image;
- shows the 3D preview on the page first;
- never downloads a project file as a side effect of the Generate action;
- provides an explicit no-cost `DEMO / MOCK` generation path that changes the procedural Three.js scene;
- uses the same validated `WorldBlueprint + AssetSpec` contract as AI Game Lab;
- keeps explicit GAME and MAKE outputs;
- forces MAKE to `validation-required`;
- exposes downloads only through explicit Export / Download buttons;
- keeps the old Forge Studio available only as a labelled legacy reference link.

## LIVE boundary

The approved LIVE Astra pilot remains exhausted at **4/4 reservations**. Therefore this fix does not make a new paid API call and does not silently reopen public LIVE generation.

When a future owner-approved LIVE allowance is armed, the native shop can use the existing server-side `/api/blueprint` Astra path. Until then, the visible generation action is explicitly `DEMO / MOCK` and the optional image is previewed locally but not interpreted by AI.
