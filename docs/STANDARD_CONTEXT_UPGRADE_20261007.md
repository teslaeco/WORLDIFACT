## What the installed source still repeats

1. PR214's `context_policy.initial_task` puts the complete factored scene schema,
   complete geometry guide, reference order and original user inputs in the
   initial task. The exact-source zero-photo schema is 15,501 Unicode characters;
   the full original guide is 15,426. The gateway keeps the incoming history and
   appends current guidance before the unchanged input-token/budget check. The
   source therefore still permits repeated large, authoritative input on every
   later request. PR214's earlier compaction is present; it is not the missing fix.
2. The inherited `JobTools.snapshot` in `blender_mcp.py` is already bounded
   to 12,000 nested-wire bytes, with lossless revision/SHA-bound pages for larger
   sections. For small sections it inlines scene, accumulated edit code and
   report. `build` returns that snapshot; PR214 then asks the inspection exec to
   print another current summary. This can repeat scene/edit text. It is bounded
   duplication, not an unbounded snapshot bug. The latest report and completion
   assessment can change and must not be silently dropped.
3. The exact runner does not override Code Mode's configured exec wait. Pinned
   Codex 0.154 has a 30,000 ms default in its core config, a 10,000 ms protocol
   fallback and a 10,000 ms default for `wait`. PR214 recommends a 120,000 ms exec
   pragma but does not give that duration for subsequent waits. Short polls are
   a plausible additional source of billed full-context turns; exact observed
   exec/wait arguments are required before assigning that cause to a real job.
   A zero-second default is not supported by this pinned source.

context reduction for every scene. It introduces a discovery turn and must pass
genuine offline transport checks plus separately authorized real-model quality
